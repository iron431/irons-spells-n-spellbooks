### Changes
- Tyros now uses cast components instead of attribute modifier hack to quickly channel his midair fireballs
- Cast animations now play at the speed of the final cast time, including cast-time changes from `BuildCastContextEvent.Post` listeners and mob component patches such as Tyros' quick fireball
- Hand-held imbues (swords, staves, wands) now rank with armor imbues in the skill bar and wheel instead of after them
- Shadow Slash now reads its dash distance and hit radius from the cast range and cast radius components, so spell range and spell radius attributes affect it
- A flat (ADD_VALUE) bonus to spell radius, range, teleport range, piercing, ricochet, healing, damage over time, projectile speed or effect duration now applies to spells that never set that value. These add flat to the spell's value, including Projectile Speed, which previously multiplied; use ADD_MULTIPLIED_BASE for percent bonuses
- Mobs casting Fire Breath, Dragon Breath, Poison Breath or Cone of Cold now track their target while channeling, like Ray of Siphoning
- Keybinds moved to the `key.skillcasting.*` names. Bindings saved by 3.x (spell wheel, wheel toggle, cast, bar modifier, quick casts) are carried over once on first launch
- Chain Lightning cast from a dispenser now renders its first zap
- A cast's held model and particles no longer carry over into a cast started in the same tick (for example quick-casting while channeling)
- Owned summons glow again (`ownedSummonsGlow` and `summonGlowColor` in `irons_spellbooks-client.toml`)
- Summoned Swords now reads its health from the summon health component, so summon health changes apply to it. The component holds the plain sword's health; the claymore and rapier keep their ratio to it, so default values are unchanged
- Players who come into range of an entity mid-cast (such as a boss channeling) now see the cast, with its progress, instead of nothing until the next cast
- Saved data naming a skill, cast component, upgrade orb or affinity that no longer exists (for example after removing an addon) now drops only that entry with a warning. Previously a spellbook with one unknown spell failed to load entirely, and an unknown entry in cooldowns, recasts or cast components wiped the player's casting data
- Burn durations from fire spells can now be changed by addons; default values are unchanged
- Freeze durations from ice spells can now be changed by addons; default values are unchanged

### API
- Added `createLevelRenderable` to AbstractSkill
  - Now auto-populates a level renderable if set on `onClientCastStart`
- Added `levelRenderableRotatesWithCast` to AbstractSkill
- [Breaking] `createClientTicker` now takes a CastContext
- [Breaking] Removed `SpellSummonEvent` and `SetSummonOwnerEvent`. Replaced by the `SummonEvent` suite (`api.events.summon`):
  - `SummonEvent.Pre` (cancellable, entity substitutable) and `SummonEvent.Post`, posted by the new `SummonManager#summon(CastContext, ...)` for every cast-produced summon (Summon Polar Bear now fires them too)
  - `SummonEvent.OwnerSet`, posted by `SummonManager#setOwner`
  - `SummonEvent.Unsummon` with a `Reason`, posted by the new `SummonManager#unsummon` (expiry, dismissal, owner dimension change, anti-magic)
  - Owners are exposed as `CasterRef`; `getOwnerEntity()` covers the entity case
- Cast-produced summons are now attached to the cast context (`ATTACHED_ENTITIES`)
- [Breaking] Removed `MagicSwordItem`; use `ExtendedSwordItem.imbued(properties, skills...)`
- [Breaking] Removed `ImbuableChestplateArmorItem`; use `ExtendedArmorItem.imbuable(properties)` at registration
- [Breaking] Removed `AbstractSpellCastingMob#attemptInitiateCastSpell`; use `SkillcastingUtils.initiateMobCast` (deliberately skips `canBeCastBy`; checked casts go through `SkillcastingManager.attemptInitiateCast`)
- [Breaking] `CastSource.type` now identifies what kind of source cast the skill; for equipment gathered by skillcasting it is the registry id of the data component holding the container (e.g. `irons_spellbooks:imbued_container`). `SpellCastSources.SPELLBOOK/SCROLL/IMBUE` are those ids.
- [Breaking] Removed `CastSource.of(EquipmentSlot)` and `CastSource.of(String)`; use `CastSource.of(type, slot)`
- [Breaking] `GatherSkillSelectionEvent#addSource(container, EquipmentSlot, priority)` is now `addSource(container, DataComponentType origin, EquipmentSlot, priority)`
- Datapack `power_multiplier` and `mana_cost_multiplier` and the `imbuedConsumeMana` server config are applied again
- [Breaking config] `swordsConsumeMana` and `swordsCooldownMultiplier` in `irons_spellbooks-server.toml` are now `imbuedConsumeMana` and `imbuedCooldownMultiplier`; re-apply custom values
- `disableAdventureModeCasting` works again
- Removed the dead client config `spellBarDisplay` (the skill bar belongs to skillcasting)
- The 3.x HUD options are back, now in `skillcasting-client.toml` under `UI`: skill bar display mode (Always, Contextual, Never), anchor and offsets; recast overlay anchor and offsets; skill wheel `ignoreGuiScale` and size multiplier. Values set in `irons_spellbooks-client.toml` under 3.x do not carry over. Corner anchors now keep the skill bar and recast overlay fully on screen (they clipped off the edge, and `TopRight` drew at the bottom left); recasts anchored at the bottom stack upward
- Fixed: skill selection reset on every equipment change; summons treated every other owner's summons as allies; an empty spell config file aborted the whole config load; a spell config pointing at an unknown school crashed on first cast; school and rarity caches went stale after `/reload`; removed cast components never reached the client; Pyromancers had no attack spells
- Added `SpellcastingComponentTypes.DIG_DEPTH`
- Restored 1.21 values for Blaze Storm, Ice Block, Fireball, Magma Bomb, Throw, Starfall, Magic Arrow, Summon Horse, Sculk Tentacles, Arrow Volley, Lightning Bolt, Poison Arrow, Spectral Hammer, Telekinesis; fixed Shadow Slash hitbox and Gust strength scaling; Earthquake, Root, Stomp, Thunderstorm apply school and config power again
- [Breaking] Animation mechanism moved to skillcasting: `AnimationHolder`, `IAnimatedCastingMob`, `IAnimatedAttacker`, `AttackAnimationData`, `AttackKeyframe` now live in `io.redspace.skillcasting.animation`; `AnimationHelper`, `IronPlayerAnimationData`, `IronsAdjustmentModifier` in `io.redspace.skillcasting.client.animation`; `SyncAnimationPacket` and `PlayPlayerAnimationPacket` in `io.redspace.skillcasting.network`
- [Breaking] `CAST_START_ANIMATION`, `CAST_FINISH_ANIMATION`, `ANIMATION_SPEED` moved from `SpellcastingComponentTypes` to `SkillcastingComponentTypes`
- `ANIMATION_SPEED` is no longer set during context build. When unset, cast animations derive their speed from the final cast time; set it to override
- [Breaking] `getCastStartAnimation()` and `getCastFinishAnimation()` are now `provideCastStartAnimation(CastContext)` and `provideCastFinishAnimation(CastContext)` on `AbstractSkill`; `AbstractSkill` defaults are pass/stop, `AbstractSpell` keeps the cast-type defaults
- [Breaking] `AbstractSkill#getCastStartSound` and `getOnCastSound` renamed to `provideCastStartSound` and `provideOnCastSound`. Convention: `provide*` hooks compute a base value that is stored into the cast context during context build; `get*` helpers only read stored components
- [Breaking] Removed `MagicData#getCachedCastingEquipmentSlot`; use `SkillcastingData#lastCastSource`
- [Breaking] `Skillcasting.init` now takes the `ModContainer`
- [Breaking] Animation resource ids moved to the `skillcasting` namespace: player animation layer `skillcasting:animation` (was `irons_spellbooks:animation`), packets `skillcasting:sync_animation` and `skillcasting:play_player_animation`, components `skillcasting:cast_start_animation`, `skillcasting:cast_finish_animation`, `skillcasting:animation_speed`
- `showFirstPersonArms` and `showFirstPersonItems` moved from `irons_spellbooks-client.toml` to `skillcasting-client.toml` (existing values reset to defaults)
- [Breaking] Added `ISkillContainer#getSelectionPriority()` (default `OTHER`); the library's equipment-slot auto-registration uses it instead of a per-slot rule. `GatherSkillSelectionEvent#addSource(container, origin, slot)` uses it too; the overloads taking an explicit `SkillSelectionPriority` override it; a data component holding a base `SkillContainer` now ranks `OTHER` in every slot (was `ARMOR`/`HANDHELD` by slot). Migrate by subclassing `SkillContainer` and overriding `getSelectionPriority`, or pass an explicit priority from a `GatherSkillSelectionEvent` listener
- `SkillContainer` is now safe to subclass: subclasses pass an `ISkillContainer.Factory` to the protected constructor, `copyWith` is final and rebuilds through it, and `mutableCopy()`/`toImmutable()` preserve the subclass. Added `ISkillContainer.streamCodec(factory)`
- Added `ImbuedContainer` (`ARMOR`) and `SpellbookSkillContainer` (`PRIMARY_SKILL_SOURCE`); `IMBUED_SPELL_CONTAINER` and `SPELLBOOK_CONTAINER` deserialize to them (same wire format) and the `ImbuedContainer`/`SpellbookContainer` helpers always produce them
- [Breaking] `SkillContainer` constructors are private; build base containers with `SkillContainer.fromSerialized(size, wheel, equip, slots)` or `ISkillContainer.create(...)`
- Skill containers with a slot index outside their size now decode with those slots dropped instead of throwing, and a negative size is rejected; `SkillContainer.CODEC` now shares `ISkillContainer.codec`
- Saved skillcasting data with a missing `cooldowns`, `recasts` or `selection` field now loads with that part empty instead of failing
- The cast component, position resolver and direction resolver registries are now synced, so a client missing an addon component gets a registry mismatch screen instead of a disconnect
- [Breaking] Renamed spell identifiers to skill in `ISkillContainerMutable` (`setMaxSkillCount`, `setSkillAtIndex`, `addSkill`, `removeSkillAtIndex`, `removeSkill`), `SkillContainer` (`SKILL_DATA`, `SKILL_WHEEL`), `AbstractSkill.buildSkillWheelInfo` and the library `ClientRenderCache` (`relativeSkillBarSlotLocations`, `SKILL_LAYOUT`). Saved values are unchanged
- [Breaking] `ISkillContainer.Factory` replaces `SkillContainer.Factory` and `Function4` in `ISkillContainer.codec`, `streamCodec` and the `SkillContainer` constructors. `SkillContainer.equals` and `hashCode` now distinguish subclasses
- [Breaking] `SkillSelectionPriority` is now a record `SkillSelectionPriority(int order)` in `io.redspace.skillcasting.data.selection` (was an enum in `api.event`), so addons can define their own priorities; `sortOrder()` is now `order()`, and the network encoding is the order value instead of the enum ordinal. Equal priorities sort by cast source type, then equipment slot (head, chest, legs, feet, mainhand, offhand, then others by name) (`GatherSkillSelectionEvent.Source.ORDER`)
- [Breaking] `SkillSelectionManager.SelectionOption` is now an immutable record: fields are read through accessors (`skillData()`, `castSource()`, `localIndex()`, `globalIndex()`, `priority()`), `withGlobalIndex(int)` replaces writing the field, and `getAllOptions()` is unmodifiable
- Fixed: `SkillSelectionManager#copy` shared its `SkillSelection` with the original
- [Breaking] `ComponentType.Builder#synced` and `ComponentType#streamCodec` take `StreamCodec<? super RegistryFriendlyByteBuf, T>`; removed `StreamCodecUtils.INT`, `FLOAT` and `UUID` (use `ByteBufCodecs`); `StreamCodecUtils.VEC3` and `VEC2` are now `StreamCodec<ByteBuf, ...>`
- [Breaking] `PositionResolver.Type` and `DirectionResolver.Type` now take a `MapCodec` before the stream codec; every resolver type must supply one. Added `PositionResolver.persistentCodec` and `DirectionResolver.persistentCodec`
- The position and direction resolver cast components are now persisted
- [Breaking] Skill events are split into top-level `SkillCastEvent` (Check/PreCast/PostCast/Complete) and `SkillRecastEvent` (Start/Finish) families (both extend `SkillEvent`): `BeforeCastStart` is `SkillCastEvent.PreCast`, `OnCast` is `SkillCastEvent.PostCast`, `OnCastComplete` is `SkillCastEvent.Complete`, `OnRecastStart` is `SkillRecastEvent.Start`, `OnRecastComplete` is `SkillRecastEvent.Finish`
- Added `SkillCastEvent.Check`, posted right after `canBeCastBy` for checked (player-attempted) casts only; its result replaces the skill's, including the action bar message. Added `SkillCastEvent.PreCast#cancelWithMessage`, which shows the message on a player caster's action bar. `SkillCastEvent.PreCast` gates every cast
- [Breaking] Every recast end (all casts used, timeout, forced removal) now removes the recast before `SkillRecastEvent.Finish` and then triggers the cooldown once. `SkillRecastEvent.Finish` listeners see `hasRecast` false on every path (it was true when all casts were used), and `AbstractSkill.onRecastFinished` overrides now run after the removal too
- [Breaking] `AttributeRegistry#simpleAddition`, `simpleScale`, `modifyComponentAsBase` and `modifyComponentAsBaseInt` are removed; spell attributes now modify cast components in one place. The attribute's own base is ignored. A component the spell did not set is only created by a flat modifier, starting from 0
- [Breaking] `SchoolType` is built with `SchoolType.builder()`; both public constructors are removed
- [Breaking] `WizardRecoverGoal` is now `WizardRecoverGoal<T extends PathfinderMob & IDrinkPotions>` and `SpellBarrageGoal` no longer requires an `AbstractSpellCastingMob`; their protected `spellCastingMob` fields were removed
- Added `SkillcastingComponentTypes.FIRE_TICKS` and `FREEZE_TICKS`. Spells set their burn and freeze durations there, so attributes and `BuildCastContextEvent` listeners can change them; `ISkillProjectile` carries both.
- `AbstractSpell#getDamageSourceDirect(ctx)` and `getDamageSourceIndirect(ctx)` are replaced by `getDamageSource(CastContext, boolean direct)`
- Added `AbstractSpell#getDamageSource(projectile)` for skill projectiles: it uses the projectile's owner and applies its fire and freeze ticks
- Removed the cone projectile entity types (`cone_of_cold`, `dragon_breath`, `electrocute`, `fire_breath`, `poison_breath`, `gust`), their `EntityRegistry` entries, `AbstractConeProjectile` and `ConePart`. Gust now hits with `SkillcastingUtils.collectConeTargets` and draws with the `gust` particle
